## Mechanism and falsifiable prediction

Load exactly16 physical tag bytes only when16 remain. Compare to the requested tag; for folded tag1, OR equality tozero so both stored0/1 match. Produce exact per-byte matches, so whole-vector matches need no candidate-byte recheck. On little-endian AArch64, a compare result containing00/ff bytes can be reinterpreted as eight16-bit lanes, shifted right4 and narrowed to eight bytes. Its64-bit representation contains one nibble per original byte:0 orf. Enumerate only nonzero masks with ctz(mask)/4, clear the entire selected nibble (not just one bit), and emit original physical-order positions; map through count−1−physical when reversed. This is a candidate mechanism description, not a code patch or promise of particular generated instructions.

Use the original source logic on remaining8-byte words and scalar bytes, including its false-positive-byte recheck where applicable. Guard the native path explicitly for supported AArch64 NEON and little-endian lane interpretation; original fallback elsewhere. No alignment assumption, speculative tail vector load, overread into memberrecords, count mutation, new allocator state or cache is allowed. Source-only helper/includes change; sizeof structures and tree-owned bytes identical.

## Ranked alternatives

1. Selected: exact16-byte NEON compare/nibble enumeration. It directly addresses the profile's complete-word work while bounding changes to one helper; x86's efficient movemask is not assumed to exist on ARM.
2. Portable exact scalar byte mask, eliminating conservative-match rechecks. It targets only the smaller recheck component and may add enough ALU/constant work to lose. Lower confidence without first measuring generated code; do not combine with NEON in this population.
3. Two-word scalar unrolling or tag1-specialized loop splitting. The compiler already specializes substantial branches in the mapped code; evidence for a remaining bottleneck is weaker, and code-size/setup costs may dominate. Do not fill implementation slots with this different hypothesis.
4. NONE if fresh control audit, semantic feasibility or implementation/codegen review fails. No artificial requirement to produce a winner.
