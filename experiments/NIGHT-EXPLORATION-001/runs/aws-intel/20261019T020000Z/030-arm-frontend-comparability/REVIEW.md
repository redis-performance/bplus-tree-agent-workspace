All line numbers refer to the immutable inputs above, not a later working tree.

Both use the same deterministic RNG, first16 RNG outputs for the hash seed, Fisher–Yates order and binary member bytes (little-endian ID then x padding). With an identical seed and size the logical insertion permutation would match because key creation consumes no RNG; the executed primary/guard seed sets differ. H4 records a construction fingerprint; primary does not. No assertion of matched physical layouts follows from these similarities.

`zbtScoreToOrdered` (`src/zset_btree.c:320`) transforms exact IEEE bits using complement/sign-bit mapping. `zbtScoreEncoding` (:916) derives leaf base, trailing differing-bit shift, and packed width from each leaf's exact score set. A numeric translation around zero therefore is not a bitstream translation. `zbtScoreLeafScore` (:498) uses width, physical reversal, bit position, optional ninth byte and base reconstruction. We have no retained per-leaf census for these executed primary/H4 fixtures. Width histograms, cross-word rates, zero/64-width frequency, reversal, occupancy, linked-leaf transitions and actual addresses remain unknown. Same tree-owned byte total would not prove equivalent layouts.

## Measurement/correctness assessment and minimum next evidence

No actual correctness defect, mismatched candidate/reference build setting, or invalid timer interval was found in this review. Both clocks surround the intended repeated traversal loop, with assertions/checksum consumers retained and exact within-pair outputs/memory. Every rejected H4 cell had qualified independent A/A and six effects above+1%. Distinct consumers and caches do not waive a real supported-API guard. Positive integer primary conversion is defined for its bounded fixture. H4 bit checksum arithmetic is unsigned modulo2^64, so overflow is defined; the separate exact per-record oracle prevents treating aggregate checksum equality alone as complete semantics. A future diagnostic must not copy the primary unsigned numeric conversion onto negative/out-of-range fixture scores.

Before an optimization proposal, the smallest useful diagnostic packet is:

1. Read-only actual-ELF mapping for these four protected binaries: source-linked caller and IteratorNext disassembly/symbol ranges, complete mask instruction dependencies, linked addresses/alignment, and before/after hashes. Use original binaries; no recompilation as a substitute for their code. If unavailable, explicitly preserve that gap.
2. Separate untimed exact-fixture census for original primary and representative forward H4 integer mask4 at100K, with each frozen seed and construction unchanged. Record packed width/shift, ninth-byte paths, leaf occupancy/reversal and linked transitions. Any diagnostic access to internals must remain outside original timing binaries and validate identical fixture outputs/owned bytes. This identifies whether comparing the same output mask actually exercises different decoder paths.
3. A newly preregistered, bounded matched scoped profile of baseline/A for both unchanged frontends on those original fixtures, serial on the authorized ARM runner, fixed order/captures and known-work/disabled controls. Map caller versus decoder versus transition samples to each actual binary; preserve unknowns and sampling precision. Require enough precision to distinguish a~3% effect, or report insufficient attribution. A sparse baseline-only profile cannot explain opposing candidate effects.

Only after this evidence could an additive diagnostic isolate one factor at a time (consumer, score distribution, warm-up or work count), with its own source freeze, semantic controls and A/A. Such a diagnostic would be a separate referee requiring requalification; it could not replace or repair the failed frozen guard. This document prepares no execution driver, grants no runner work, and selects no optimization. Prior REJECT remains final; source NONE; no population count changes.
