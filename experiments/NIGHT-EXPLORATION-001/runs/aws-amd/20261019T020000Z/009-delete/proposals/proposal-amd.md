# Independent AMD proposal: unconditional exact offset assignment

Author `/root/aws_amd`, native session agent; exact serving model and measured token/USD cost unknown. Uses common packet a04b9f69d and baseline8fab511e. No Intel/ARM proposals read. Fresh A/A is still running; no candidate code or timing exists.

Propose one narrow hypothesis: expressing the final compact-record offset adjustment as an unconditional assignment of the exact selected result will let Clang generate packed compare/select/add/store operations instead of SIMD comparisons followed by per-lane conditional scalar stores. Only the final `if (compact_records)` loop in zbtScoreDeleteInPlace changes. Preserve its enclosing condition, packed score/tag/offset relocation, record moves and ownership, and ancestor update order. Do not combine with packed-bit moves, offset-relocation fusion, tag-copy removal, allocator, index lookup or builder changes.

The candidate would load each current uint16_t offset once, choose either its original value or its original value plus deleted_bytes using the same unsigned predicate, and assign the exact value back. Source forms and compiler output are implementation-population questions, not permission to force superficial differences. Portable arithmetic is preferable to an ISA-specific path if it produces the required code; all normal compiler flags stay frozen.

Evidence: exact baseline assembly has two vector comparisons per16offset body and many tests, extract-lane and conditional scalar stores. Matched1M samples attribute5.496% of scoped periods/101events to loop setup, body and tail.100K17.116% rests on only7events and is not a reliable headroom estimate. Counts do not establish misprediction rate: sorted/partly ordered records may yield predictable predicate runs. The proposed mechanism is fewer instructions/branches and efficient packed stores, not a promised branch-miss reduction.

Predictions/falsification: generated code must remove the repeated scalar conditional stores from the compacting loop while preserving bounded tails. If Clang already selects equivalent work or the rewrite retains the same conditional-store expansion, mechanism selection has failed before performance claims. The modest1M5.5% nominal share requires a substantial loop improvement to reach2% end-to-end; inability to meet every frozen block at both sizes means rejection. If timings improve but matched scoped instructions/cycles/loop evidence cannot explain the effect, PARK. Extra unchanged-value stores might increase store traffic and erase gains; retain this counterhypothesis.

Semantic/alias review: offsets points into the leaf-owned writable offset array after all relocation has completed. deleted_offset, deleted_bytes and count are scalar values; the loop does not read an alias that needs the old value from another element. Writing an unchanged uint16_t value has no intended observable effect on this non-volatile, non-atomic private structure; do not introduce stores beyond count or to packed-score/tag bytes. Preserve integer promotions and final uint16_t conversion exactly, including the low-bit behavior of addition rather than assuming deleted_bytes is small. No change to finite scores, signed-zero ordering, physical reversal, external allocation/free sequence, index IDs or iterator invalidation. compact_records=false must execute no added adjustment work.

Required tests: unchanged original suite and offset/packed-move/ownership models, especially first/last/only-element deletion, threshold equality, zero/single/all/mixed adjusted values, count below/at/above vector boundaries, reversed physical leaves, inline/external records and non-compacting score updates. Validate exact entire offset array and surrounding bytes against the original conditional scalar rule in a bounded independent oracle if existing tests lack this coverage. Keep no-overrun, sanitizers and source-local fallback checks when relevant.

Performance guards must include original operations at five sizes, update paths with compaction disabled, binary/member length boundaries8/319/320/321/1024, reversed/edge and range deletion, ties/signed-zero layouts and dense leaf counts. Freeze concrete fixtures/seeds before timing; unimplemented or noisy guards block acceptance. Fresh controls must qualify; no retries/operation changes. No source adoption overnight.

Recommendation: select this single hypothesis for implementation only if the fresh controls and chair review support a bounded screen. Choose NONE if insufficient headroom or semantic evidence; never reuse rejected packed-move/builder variants under this label.
