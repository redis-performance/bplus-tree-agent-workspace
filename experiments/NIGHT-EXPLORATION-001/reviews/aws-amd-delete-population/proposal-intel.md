## Supported conditional hypothesis

If a separately justified target ever qualifies, express the final compact-record offset adjustment as an unconditional write of a selected unsigned value, enabling packed add/select/store instead of per-lane conditional stores. Each owned uint16 offset would receive its old value plus deleted_bytes when old<deleted_offset, otherwise its exact old value. Change only this final loop, inside the existing compact_records condition. Do not alter record movement, packed scores, builder, earlier top-gap shortcut, count/path updates or external allocation handling.

The common1M profile attributes101/1844 samples (5.496%) to this loop's exact ranges. Clang18 assembly already compares16 lanes but extracts masks into individual scalar conditional stores. Census shows~67.6 offsets per compaction,~49.5% changed,~98.6% mixed loops and~88.6% offsets in full16-lane groups. This supports testing store structure, not assuming the existing scalar-looking C lacked SIMD compares. Census is not branch-miss evidence. The100K sample is only7 loop hits out of59 total, too small for quantitative headroom. These are sampled attribution figures, not a rigorous cycle-cost bound.

The preferred source expression is portable unconditional assignment with a value selection; an arithmetic0/1 mask is an equivalent implementation option if the compiler leaves per-element branches. The three implementers should not manufacture differences. Handwritten SSE2 is a larger portability and unsigned-compare burden and should not be selected before the portable expression's codegen is known. A formulation that still emits the same conditional-store body fails the mechanism prediction; extra source complexity then has no supported rationale.

## Semantics and guards

The loop runs after overlapping offset relocation is complete. It writes only the current count uint16 cells; hash tags start immediately after that array, so no rounded-up vector tail access is allowed. Capture each old value before replacing it. The leaf header/count fields precede leaf data; no alias permission, restrict qualifier, allocation-layout or alignment assumption should be invented. Existing code already accesses these cells as uint16. They are ordinary writable owned storage, and preserving unchanged values with extra stores has no promised observer distinction under the mutable tree's existing invalidation contract. This does not permit writes outside the array.

Preserve unsigned comparison over all0..65535 offset values. Addition has original size_t intermediate and uint16 assignment truncation; any narrowed delta or mask must be proved modulo2^16 equivalent, not justified by typical small inline records alone. Compact_records=false must still skip all adjustments, including score-update/external-record transfer paths. No free/ownership behavior changes. Keep last/first physical deletion, descending/reversed leaves, top-gap/record_start cases, mixed and zero-adjustment loops, long/external members, score-width relocation, resize/index references and update-then-delete histories in correctness coverage. Retain original tests/sanitizers and exact bytes/scores/ranks/SCAN/member membership/accounting checks.

Performance guards would include no-change compactions (extra stores may lose), tiny/tail-only loops, mixed/all-change synthetic offset controls, long/external member deletes, update paths and all original operations. Exact tree-owned memory must remain equal. Do not infer all-change behavior from a census that observed no all-change loops. Codegen/profile checks must verify bounded packed loads/stores and reduced branch/store sequence, with unchanged compiler flags/assertions/hash/allocator/referee.
