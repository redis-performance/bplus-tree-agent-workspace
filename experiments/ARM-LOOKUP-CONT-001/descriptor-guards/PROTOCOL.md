# H6 member-consumer guards — provisional revision 0

These four supplemental guards cover member-address consumers affected by H6's masked record descriptors. They change neither the original lookup referee nor the existing score-only guards. This directory is a **provisional protocol awaiting independent review and controller freeze**; it does not authorize measurement. The author implemented H6-A and is not an independent reviewer of A or this harness. Public participant role: descriptor-guard implementer. Detailed backend provenance remains private; exact model/token costs are unknown.

## Fixture and cases

Each fresh process creates 529 unique binary members with scores equal to their one-based fixture IDs. There is one empty member and 16 members at each length 1–17, 24, 32, 64, 127, 128, 129, 252, 253, 254, 255, 318, 319, 320, 321, 512 and 1024. First bytes are replica IDs 0–15; subsequent bytes follow the explicit deterministic formula in `guards.c`, including embedded zeros every seventh position. Reserve 529, then insert alternately from the lowest and highest remaining score. Caller-owned SDS buffers remain separate from tree-owned bytes. Seed 17 controls SipHash; 29 and 43 are correctness/held-out confirmation seeds with separately qualified controls if used for performance.

The 465 members shorter than 320 bytes cover all three descriptor codebooks, including coded and uncoded boundaries 7/8, 14/15, 16/17, 127/128/129 and the inline header transition 253/254. The 64 members of length at least 320 use the existing external-storage threshold. Encoding eligibility differs by variant, intentionally: B hints only 0–7, A 0–14, C its selected codebook. This is a public-API fixture, not instrumentation of private descriptors. Physical encoding invariants remain the existing H6 correctness oracles' responsibility. It does not manufacture externally stored short records; those remain separately covered by the dedicated external-record oracle.

| Case | One sweep | Provisional sweeps | Operations/process |
| --- | --- | ---: | ---: |
| member-forward | Forward iterator returning member pointer, length and score for every entry | 1,000,000 | 529,000,000 returned members |
| member-reverse | Reverse iterator returning member pointer, length and score for every entry | 1,000,000 | 529,000,000 returned members |
| lookup-inline | Scored raw lookup of each of 465 inline members, immediately followed by its absent query | 100,000 | 93,000,000 queries; exactly half hits |
| lookup-external | Scored raw lookup of each of 64 external members, immediately followed by its absent query | 500,000 | 64,000,000 queries; exactly half hits |

Lookup misses preserve the member length and all bytes except bit 7 of the first byte; stored first bytes are 0–15 so these are provably absent. The empty member's absent partner is the one-byte value 254. Miss score outputs start at -123 and must remain unchanged. Queries are fixed hit/miss pairs, not random hit ratios. Inline and external lookups are separate so a generic external fallback regression cannot be canceled by a short-inline speedup. The inline case still aggregates coded/uncoded lengths; it does not independently bound every length. Misses are not constructed to force a tag collision or displaced probe: no such coverage is claimed. Generic fallback hits are guaranteed by the uncoded/external fixture lengths.

Iterator loops consume returned bytes using bounded first/middle/last-byte samples weighted by ordinal, plus full length, score and ordinal-weighted score sums. Empty members perform no byte read. This adds three reads per nonempty returned member, deliberately avoiding a full-string hash dominating the address-consumer workload. Exact full-byte equality, order, scores, length, hit/miss results and untouched miss outputs are checked before and after every loop outside the clock. End-of-iteration is checked in both directions. The timed checksum is a diagnostic, not a claim of cryptographic collision resistance; final full-member validation provides exact equality. No mutation is performed by the workload itself, although public lookup may advance incremental index maintenance.

## Timing boundary, correctness and memory

`verify` accepts 1–8 sweeps, executes the same loop and never calls the clock. Local validation uses 1/2/5/8 sweeps, all four cases and seeds 17/29/43 against baseline and H6-A/B/C in both native and ASan/UBSan builds: 384 cells. `check_oracle.py` independently derives all checksum fields from integer fixture IDs and generated bytes, without calling the tree or sharing the C accumulation helper. All outcomes must match across implementations; tree-owned memory is retained separately rather than removed from comparison.

`measure` executes 1,000 untimed warmup sweeps, checks warmup sums, validates the tree, computes expected final sums and samples owned memory. The clock wraps only `run`; setup, full comparisons, expected-value construction, printing and cleanup are outside. Loop safety assertions and checksum accumulation are inside and identical across variants. Immediately after stopping the clock, capture `owned_bytes_after` **before** validation lookups can finish a rehash. Then validate sums and the full tree and separately report `owned_bytes_after_validation`. The memory gate uses pre-loop and immediate post-loop endpoints, never substitutes the validation endpoint. Endpoint accounting does not measure transient peak allocation.

The separation of forward/reverse cases and immediate memory endpoint follows the existing guards' revision 1 corrections. Any harness correction after this proposal must preserve the failed version and observations and produce a new referee hash and protocol revision before fleet use. `failed-attempts/build-case-terminator/` retains the initial missing shell `esac` failure, caught before compilation; it produced no performance data.

## Limits and TMA

These guards cover modest trees, distinct integral scores and deterministic read traffic. They do not time mutation, defragmentation, reverse physical leaf storage, external short records, all optional output combinations, active-resize traffic or forced hash collisions. Existing mutation/invariant/oracle coverage remains mandatory. Scored raw lookup retains hashing costs, especially for long external members; results apply to this API path, not a claim about isolated descriptor or equality cost.

For baseline and H6-A/B/C, Frontend_Bound, Bad_Speculation, Backend_Bound, Retiring and child pipeline-slot shares are **unavailable** for these new workloads. No profile or TMA collection was performed. ARM collector scope/formula qualification remains unavailable; no existing Intel or whole-process category is transplanted here.

Own enabled-tool discovery found no callable cpu-perf/library_status tool. The controller's actual shared descriptor consultation is recorded in `../H6-selection.md`; no supporting passage established a gain. This author claims no new consultation. The harness follows the changed public consumer paths, not an asserted pipeline bottleneck. No fleet access, measurement, commit or push was performed while preparing this directory.
