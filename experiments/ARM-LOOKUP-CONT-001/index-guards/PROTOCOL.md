## Fixed fixture and public operations

Every fresh process sets the original SipHash seed bytes to `(seed + 29*i) & 255`, for i0–15. Seeds17/29/43 are deterministic correctness inputs;17 is proposed discovery,29/43 held-out performance confirmation. No tree or hashing source changes are made. Generate544 distinct128-byte binary keys. Key i starts with its four-byte little-endian ID and a four-byte little-endian nonce. Other bytes are zero at multiples of7 and `(i*17+j*29)&255` elsewhere. Select the first nonce below10,000,000 for which the **public current** `zbtreeMemberHash` has low6 bits63 and high byte `i&1`. These keys force the last home bucket of a64-bucket table, folded index tag1, actual leaf tags0/1, real same-tag collisions and wraparound. Nonces, hashes and fixture digests are saved for each seed. Key generation, all hashing during that search, allocations and initial tree construction are outside the proposed measured interval.

Read fixtures reserve256 members and insert IDs0–255 with scores1–256 in ascending order through `zbtreeInsertNewRaw`. IDs512–543 are absent collision queries. All tested bytes and hashes come from the same deterministic public fixture, independently rebuilt in every binary. The512-member key pool is used only by mutation traffic. Caller-owned SDS buffers are never included in tree-owned memory.

These names deliberately distinguish traffic from internal claims. `collision-hit` contains home-resolving and genuinely displaced hits; it is not a pure displaced-only estimate. The correctness-only diagnostic determines the actual split, with no key selection based on timing or candidate results. Initial baseline seed17 has30 home-resolving hits and226 displaced hits, maximum30 buckets, including wraparound. Every absent query passes the original home filter, encounters a full home bucket and must continue into the probe run. Merely overflowing a bucket would not have proved this: same-tag references can point at the same leaf, allowing a displaced entry's member to be found from a different reference at home. The diagnostic checks the bucket actually returned by the existing table finder.

Churn starts with128 members, **without reserve**, and setup validation finishes any pending resize. Each sweep inserts IDs128–511 with scores i+1, calls `FindForAdd` and `UpdateScore` for each of512 members to set score513+i, then deletes IDs511 down to128. That is384 inserts,512 find calls,512 updates and384 deletes:1,792 public API calls/sweep, including1,280 mutations. Creating replacement members, allocating/repacking leaves, public lookup advancement of migration, tombstones, growth and shrink are deliberately part of this workload. Initial object/key construction and final validation are outside. The first and subsequent sweeps do not have identical physical layouts; this is declared mutation traffic, not steady packing. No internal resize primitive or synthetic hash is called by the public workload.

Scan always follows the returned opaque cursor to zero. Its callback consumes the returned length, ID, score and first/middle/last bytes and maintains a per-ID callback histogram. Verification additionally compares all128 returned bytes. Every member must occur in each completed verification walk. Repeated callbacks are legal: the initial baseline seed17 walk uses9 calls and482 callbacks for256 unique members. Counts and histograms are compared exactly with baseline, while the independent model checks all returned IDs/scores and byte checksums. Report API calls, callbacks and unique completed member coverage separately; never equate scan calls with returned members. No mutation occurs during a scan walk.

## Correctness, resize evidence and memory

`guards.c` supports `verify CASE SEED SWEEPS`, restricted to1–8 sweeps. Its verification branch never calls `now_ns`; fixture generation also has no clock. Local qualification links `clock-deny.c` with `--wrap=clock_gettime`: any call from the executable to the harness's sole clock API aborts. The driver verifies that no unresolved clock_gettime symbol remains and the abort wrapper is linked. Verification modes use the same API sequence as measurement mode; additional checks perform no maintenance-advancing tree call inside the operation loop. Final public validation is outside it. Diagnostic binaries reject `measure` before fixture construction and can never qualify for timing.

Public builds link the original/candidate C file separately. Diagnostic builds include that exact file solely to inspect state without writing it. `observe` reads active old/new tables before/after API operations, records growth/shrink and observed completion transitions, and walks leaves to witness changes in surviving members' leaf IDs. It does not advance rehash, call repair routines directly or manufacture migration states. A changed leaf ID is a repair obligation whose resulting public lookup is checked; it is **not an exact count of calls to the reference-finder**. Public source flow connects those leaf moves to `zbtIndexMove`. The full scan's same-tag resolution also calls `zbtIndexTableFindReference` as required by the unchanged source. Assertions/diagnostic state reads are excluded from normal fleet builds.

The initial two-sweep baseline diagnostic observed60 active-before states,61 active-after states,110 growth/11 shrink state samples,5 completion transitions and1,203 leaf-ID reassignments. These establish actual public mutation/resize coverage, not guaranteed time spent in those states. Saved final diagnostics additionally report59 states with nonzero old/new table used counts and57 reassignments observed while resize remains active for that seed17 two-sweep cell. Nonzero used counts are physical population evidence, not proof that both tables still contain logically eligible members at every sample. This is a finite fixture and partial boundary observation, not proof that every resize branch, every migration order or every same-tag reference exchange is covered. Stable read/scan fixtures deliberately finish resizing before the loop, so **no active-resize read or scan performance claim is authorized**. A separate guard would be needed for that claim.

`owned_bytes_before` is sampled immediately before the loop. `owned_bytes_after` is sampled immediately after the loop/clock-stop, **before** checksum/full-tree validation can advance migration. `owned_bytes_after_validation` is reported separately and cannot replace the immediate endpoint. The initial two-sweep native baseline churn endpoint was26,896 bytes, falling to22,736 after validation completed pending maintenance. Pre/post equality is not a requirement for mutation; each endpoint must be reproducible per binary/case and independently satisfy the1% candidate/control bound. Endpoints do not bound transient peaks, allocator RSS or setup memory.

`run-correctness.py` checks frozen source identities, then builds baseline and H7-A/B/C in native public, ASan/UBSan public and native diagnostic modes. Each binary executes all four cases, seeds17/29/43 and1/2 sweeps:288 cells. The independent `check_oracle.py` reconstructs byte arrays from the explicit integer formula/nonces, checks the fixture digest, recomputes lookup and mutation counts/sums, validates scan histograms/byte sums, and joins every baseline/candidate row including all three memory endpoints. Functional expectations do not use another tree implementation. Hash predicates use the unchanged public implementation, with independent diagnostic path checks; there is no separate SipHash implementation in this harness. Exact logs, build identities, stdout/stderr and failure artifacts remain in this directory; local executables remain ignored.

## Limits, TMA and consultation

The fixture intentionally stresses one folded tag and one wrapped home run; it is not a production collision-frequency model. Raw lookups retain hashing costs for128-byte keys. Churn includes allocation and score movement, so it does not isolate mask arithmetic. IDs stay narrow; external values, wide IDs, zero-length members, scalar tail sizes, reverse physical leaf states and all optional-output combinations remain the existing correctness oracles' responsibility. The scan case covers folded-zero union, same-tag member enumeration and complete cursor termination. It is not a claim that active-resize scan, every scalar tail or every reverse state was timed.
