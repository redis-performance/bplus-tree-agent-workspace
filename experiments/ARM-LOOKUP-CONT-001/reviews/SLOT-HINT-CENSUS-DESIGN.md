Allocation identity is appropriately separate from descriptor addresses. Source audit confirms production ID-array stores centralize in zbtIndexSetId, whereas allocation, duplication memcpy and defragmentation relocation are independent sites. The registry must register before use, retire before free, preserve receiving identity during promotion, copy hints/seed snapshots into a distinct duplicate generation, and rebind bucket relocation using an integer key captured while live. Defragged headers or rehash descriptors do not create new bucket identities. Global generation numbers cannot repeat when registry slots or allocator addresses are reused; duplicate live keys, size/width mismatches and unknown nonempty allocations abort. Legitimate empty descriptors use null generation and no work. These are required implementation checks, not runtime coverage already obtained.

The policy preserves all original leaf-ID meanings. Only CopyLeaf/Rebuild loops can seed using their existing known physical position, with a nonnested context consumed by exactly one existing raw insertion. The original insertion chooses its own slot. Only an insertion into index slot zero can seed; every slot-zero ID write first invalidates, including same-ID writes, ordinary insertions, tombstones and reference moves. Other raw insertion sites cannot acquire a seed by searching. Duplication preserves already stale hints instead of refreshing them. No hook changes original home words, IDs, occupancy, placement, query sequence or tree allocation accounting.

Staleness must use an owned byte snapshot, never a saved record/external pointer. Codes1–96 represent positions0–95; position >= current count is a valid stale observation. Codes97–255 are impossible under this generator and therefore corruption, although a future candidate policy could treat them as unavailable. For in-range hints, the seed comparison uses the stored seed hash/length/bytes; the query predicate uses the current query hash. A different query cannot by itself make an unchanged seeded member stale. External hash rejection precedes pointer access in both applicable comparisons. Exactly one terminal classification and one applicable stale state are emitted; disabled/nonzero-slot cases use NA, out-of-range is stale, and in-range cases partition stale versus unchanged. A stale hint can coincidentally match the current query, and an unchanged hint can fail it; neither relation is collapsed.

Every eligible original leaf call remains mandatory, exactly once with original arguments and outputs, after the original tag/tombstone/live-leaf/migration checks. Shadow success cannot short-circuit it. Successful hinted outputs must agree with the original result, including requested score object bytes and logical position. Native and LTO review must verify the unconditional call, caller control flow and complete retained original leaf body; event counters alone are insufficient. Useful exposure is the set of stable unique query IDs having a hinted success and original success, separately from event totals. A failed hint followed by original success is ordinary fallback, not a diagnostic error.
