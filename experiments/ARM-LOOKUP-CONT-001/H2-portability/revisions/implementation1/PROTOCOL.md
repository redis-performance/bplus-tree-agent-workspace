# H2-B cross-ABI correctness preparation

Status: PREPARATION ONLY, NOT ADMITTED. H2 remains PARK. This proposed check can fill specific 32-bit and big-endian execution gaps for the frozen baseline/H2-B pair. It cannot qualify performance, overturn failed A/A controls, prove every architecture portable, or validate native target code generation. No source change, C execution, emulator, Docker operation, fleet mutation or timing was performed during preparation. Harness C files received local syntax-only compilation; synthetic driver tests execute only Python and mocked operations.

## Recommended setup and limits

Use one separate task-owned Debian Bookworm tools image on the owned Intel fleet, with two explicit cross targets:

| Target | Compiler | Emulator | Required guest evidence |
|---|---|---|---|
| i686 Linux | `i686-linux-gnu-gcc` | `qemu-i386` | ELF32/i386, little endian, pointer/size_t/unsigned long32 bits |
| s390x Linux | `s390x-linux-gnu-gcc` | `qemu-s390x` | ELF64/IBM S/390, big endian, pointer/size_t/unsigned long64 bits |

This is the lowest setup complexity supported by the inspected dependencies: two packaged cross compilers and one user-mode emulator package in one disposable image. It is not a measured cost or elapsed-time claim. One 32-bit big-endian target could cover both properties in one run, but would not separate pointer-width failures from endian failures; it is not substituted for this pair. A host `-m32` build depends on multilib and execution support and supplies no big-endian coverage. Rebuilding GCC15 cross toolchains is unnecessary for this correctness question. Bookworm's default cross GCC is12; disclose exact installed versions rather than calling these GCC15 results.

The controller's read-only Intel check found neither cross compiler nor either emulator. Docker and host GCC exist; the previously used `gcc:15.2.0-bookworm` image has short ID `9ca91b05c7b0`. Root must capture its full content ID before any derived build. Use it only as the immutable base for a separately tagged task image; install packages only in that new image. Do not retag or alter the benchmark image, install host packages, register binfmt handlers, mount the Docker socket inside the container, or require privileged execution.

Install explicitly, with no recommends: `gcc-i686-linux-gnu`, `gcc-s390x-linux-gnu`, `libc6-dev-i386-cross`, `libc6-dev-s390x-cross`, `binutils-i686-linux-gnu`, `binutils-s390x-linux-gnu`, and `qemu-user`. Cross libc development packages are recommendations of the GCC metapackages and must be named explicitly. Save Dockerfile, package repository metadata, package versions/dependency resolution and downloaded package hashes; freeze the resulting full image ID before compiling either source. Missing packages or dependency conflicts block the phase; do not replace the target/compiler mid-run. Root must approve any changed setup as a separate revision before execution.

Use explicit emulator commands with the target dynamic-loader/library prefix, expected to be `/usr/i686-linux-gnu` and `/usr/s390x-linux-gnu`. Verify actual installed paths, ELF interpreter and target libraries during preparation; do not infer them only from the compiler name. No binfmt registration is needed. Use the same compiler, sysroot, image, flags, emulator command and guest CPU model for both baseline and B within an ABI. Freeze explicit `-cpu max` for both emulators and retain their supported-CPU listing before admission; no adaptive CPU-model fallback after a failed test. QEMU7.2 primary [s390x](https://github.com/qemu/qemu/blob/v7.2.0/target/s390x/cpu_models.c) and [i386](https://github.com/qemu/qemu/blob/v7.2.0/target/i386/cpu.c) sources define max; live support remains gated by the pinned installed binary.

Primary package and execution references: Debian [i686 compiler](https://packages.debian.org/bookworm/gcc-i686-linux-gnu), [s390x compiler](https://packages.debian.org/bookworm/gcc-s390x-linux-gnu), [qemu-user executable list](https://packages.debian.org/bookworm/amd64/qemu-user/filelist), and [QEMU Linux user-mode documentation](https://www.qemu.org/docs/master/user/main.html). Those establish package availability and supported invocation, not that this project's adapter or test suite passes.

## Dependency and harness audit

- `qualify.sh` is not cross-ready: it hardcodes `cc`, executes produced ELFs directly, and runs both plain and ASan/UBSan modes. Preserve it unchanged. A separate reviewed wrapper must reproduce its original test command and its18 verify fixtures per binary using the cross compiler and explicit emulator. Do not run top-level `make all`, `make smoke`, or any benchmark target; they include benchmark programs.
- The original unit executable uses `tests/upstream.c`, selected `zset_btree.c`, frozen `compat/standalone.c`, frozen `vendor/siphash.c`, include paths for that selected tree, `-lm`, and `-DREDIS_TEST -DREDIS_DEBUG`. It reports57 tests. It includes reserve-overflow checks with a documented32-bit path, a1,000,000-member mutation test and resize/scan cases. Do not reduce those counts to fit an emulator timeout.
- The plain lookup fixture links the same source/adapter/SipHash without `REDIS_TEST`; `verify` branches before its `now_ns`/measure block. Only `verify CASE SEED 1` is allowed. The reviewed wrapper must reject all other modes. Link an additional harness-only `--wrap=clock_gettime` function that aborts on invocation, so accidental entry into the timing branch fails without changing the referee. Apply the same wrapper to paired binaries; no clock symbols in source are renamed or patched.
- The adapter requires Linux libc `malloc_usable_size`, malloc/calloc/realloc/free, C11, standard math, and the upstream packed SDS64 headers. It creates SDS64 strings even in a32-bit process. Cross libc headers, `libc`, `libm` and GCC runtime helpers are required; no Redis server, jemalloc, C++, threads, OpenSSL or hardware PMU is linked.
- The source uses GCC count-leading/trailing-zero and byte-swap builtins. The frozen compatibility header selects `intrev64ifbe` using compiler byte-order macros. Bit-packed scores intentionally use little-endian byte order. SipHash uses its byte-assembled portable path on s390x; i686 uses its existing x86 path. Do not define architecture/endian macros manually or force packed structure alignment.
- External records store native-width pointers via memcpy. Their size and allocator rounding can differ on32-bit, so do not import the64-bit14,272-byte fixture model. Compare baseline/B within the same guest ABI/allocator, and report actual endpoints. Do not compare absolute owned bytes across ABIs as a regression.
- The supplied output oracles include `zset_btree.c` directly, so compile each as its own translation unit plus adapter/SipHash, without separately linking `zset_btree.c`. They provide90,000 ordinary and45,000 external-record output checks per source/ABI, with no timers.
- The existing metadata oracle is B-specific: it directly references `flags`, `score_bytes` and new accessors. It cannot be compiled against baseline unchanged. Preserve and execute it unchanged for B. A separate paired oracle needs only harness-local access adapters for baseline's `isleaf`, `score_shift`, `has_external` versus B's accessors/cache; it must never edit either candidate source or hide assertions. The implementation is `paired_metadata.c` with harness-local adapters; its frozen hash requires independent review before admission.

Proposed common flags: `-std=c11 -O2 -g -Wall -Wextra -fno-omit-frame-pointer`; no LTO, native-ISA options, `NDEBUG`, fast-math, sanitizer suppression or source feature changes. These are correctness builds with a different compiler from the performance artifacts. Mandatory plain execution is separate from optional future sanitizer work. ASan address-space/runtime support under user emulation is unproven; do not claim sanitizer coverage, silently fall back after a sanitizer failure, or count a runtime failure as a source pass. A future UBSan-only extension may be useful but is outside this fixed phase.

## ABI and focused proof required before claiming coverage

Build and run a small harness-only ABI reporter for each source/ABI, including the selected C source so internal structure layouts come from the actual compiled types. It must report compiler target/version/macros, runtime byte order from a known integer's bytes, `CHAR_BIT`, pointer/size_t/unsigned-long/uint64/double sizes, double radix/mantissa/exponent, `_Alignof` values, and relevant `offsetof` values. Require CHAR_BIT8, uint64/double8 bytes, binary radix2, DBL_MANT_DIG53 and DBL_MAX_EXP1024. The actual ELF header, runtime observation and compiler macros must agree on class/machine/endian.

For i686 require ILP32 and runtime little-endian; for s390x require LP64 and runtime big-endian. Record node size, leaf `data` offset, alignment of uint64 and leaf, offsets/sizes of `moved_out`, `index_resize`, B `score_bytes` and flags. Require baseline/B equal node size and leaf-data offset within the ABI. B's64-bit static assertions must execute through compilation on s390x (node24/leaf56); i686 must actually compile the alternate pointer-width branch. Expected i686 node20/data44 is a layout prediction from the inspected fields and normal i386 alignment, not measured proof; record and review actual values rather than assuming all32-bit ABIs share it.

The paired focused oracle should retain the existing deterministic384-member/four-score-mode mutation schedule: integer/reverse/extreme/equal scores, inline256-byte and external384-byte records, score-width changes, reverse-pop, copying, page relocation/repair, deletion, compaction/shrink, and append-batch rebuild. Keep the native existing count of7,693 validations per run; require width0, width64 and reversed-leaf coverage and nonzero page relocations. Do not hardcode leaf-visit or relocation counts across ABIs because layout can change packing. Preserve host-endian key construction in the existing oracle; compare only within the same ABI, not cross-ABI traversal digests.

For baseline, recompute score bytes from count/width and check the offset pointer against `leaf->data + recomputed`; for B additionally require its cached uint16 value to match. In both, check offset alignment, count/score width range, external ownership, structural validity and optional output semantics. Enumerate all4 combinations of leaf/external flags ×64 shift values, preserving uint8 moved_out=255 and uint16 index_resize=65535; B must preserve its cache during every flag update. This tests both byte orders of the cached16-bit field under actual execution. The paired adapter must not add a fake cache to baseline or make baseline call B-only functions.

## Fixed execution matrix and stop rules

Execution requires root's fresh live owned-reservation/state check, reviewed container/image and wrapper, exact full tool/library/ELF pins, and sufficient remaining lease/cleanup time. This document alone does not admit it. Use one task output directory with an atomic single-use claim, e.g. `H2-portability-i686-s390x-001`; preserve failures and partial outputs. No automated same-phase retry or target/compiler substitution.

Freeze image setup once, then execute ABI order i686 followed by s390x. Within each ABI run baseline then B, serially. For each source, record build stderr/stdout, ELF identity and ABI proof before executing tests. The per-source fixed suite is:

1. Original57 unit tests, unchanged.
2. Original18 lookup verifies: seeds17,29,43 × hit,score,miss,long,external,update, always count1. Require verified=true,500 members, expected seed/case and positive owned bytes; pair memory endpoints within the ABI. No `elapsed_ns` or throughput fields are accepted.
3. Supplied90,000 ordinary and45,000 external-record oracle checks.
4. Paired focused metadata oracle,7,693 validations and256 flag/shift cases.
5. B only: unchanged existing metadata oracle as a separate preserved check.

A complete four-cell matrix therefore contains228 original unit tests,72 lookup verifies,540,000 supplied output checks, four paired focused runs and two unchanged B-focused runs, plus four ABI proofs. The paired oracle, ABI reporter, compile wrapper, clock guard and driver are now implemented and pinned by `files.json`; all still require independent review before execution. Direct refresh-site tests are additional to the retained7,693-validation schedule: successful leaf build, re-encoding insertion,31 fast insertions and deletion validate actual member bytes/scores/cache after every step. Width0 changes to64; count changes alter displacement; the last deletion changes272 to264 bytes, exercising both cached uint16 bytes. The reported refresh_sites count is4 distinct sites, not a claim of four total helper calls.

Bind one immutable operational-record task_started_epoch/task_deadline_epoch interval of at most30 minutes including setup/review; no phase resets it. Bound image preparation to ≤10minutes, each build ≤2minutes, unit executable ≤5minutes, each other guest process ≤2minutes, and an overall deadline earlier than lease cleanup by at least5minutes. These are resource/cleanup caps, not predicted runtimes. Start only if the controller approves sufficient remaining time; a timeout consumes the attempt and yields incomplete coverage, never a performance result or authorization to reduce counts. Use a reviewed container memory/pid limit (proposed4GiB and256PIDs); OOM is a failed/incomplete cell, not evidence of source correctness.

Stop the matrix on the first failed ABI proof, build, assertion, malformed/missing output, emulator error, unexpected nonzero exit, timeout, source/pin drift, reservation loss or baseline/B mismatch. Preserve raw output, exact command/environment overrides, emulator/compiler/library hashes, core/error diagnostics where available and every completed row. No silent skips or overwritten retries. A baseline failure is an unresolved baseline/ABI/harness limitation; a baseline pass followed by B failure is a candidate correctness failure. Both passing only closes the named emulated ABI cases. An adapter change or discovered source bug needs a new reviewed revision; frozen source is not repaired in this phase.

## Implemented admission split

`driver.py --mode image-receipt` records the separately prepared image, package receipts, tool hashes/versions, compiler target/macros, emulator CPU list and complete target-library hashes. It exports apt logs/config/metadata and nonempty downloaded-deb hash receipts. It runs no guest workload and stops with IMAGE_PREPARED. `--mode correctness` requires a separate independent review binding the exact image-receipt bytes, image ID and same input manifest. Image preparation is not correctness admission.

The canonical image construction is a root-controlled named container followed by commit; `Dockerfile` documents the equivalent recipe only. Exact full base image ID is `sha256:9ca91b05c7b07d2979f16413e8b2cd6ec8a7c80ffca4121ccab0aeba33f90460`. `prepare-image.sh` downloads into a dedicated retained archive directory, records all resolved package versions and requires a nonempty .deb hash receipt. No unowned buildkit/intermediate containers are introduced by the driver. Deployment details and record schema are in `DEPLOYMENT.md`.

Every named container has the exact reviewed cleanup owner/root/generation labels. Record/lease generation and saved coordinator identity must match. Live checks bind new cleanup Type=exec, start/runtime3min, stop15s, KillMode=control-group, SendSIGKILL=yes, timers Accuracy1us/Random0 and exact schedules/ExecStart/artifact hashes; both retired timers must be inactive. Parca must be inactive/dead/MainPID0 without residual processes, controllerCPU0, guestCPU2/sibling50offline and no other running containers. Historical unrelated stopped containers are untouched. Subprocess timeouts are clamped to remaining task/lease/timer cleanup budgets; no elapsed-performance results are emitted.

Before guest execution, the driver validates each full ELF header/program table and its single PT_INTERP, resolves/hashes the actual guest loader inside the pinned sysroot, saves lookup nm/disassembly, requires a defined and called clock wrapper, and rejects unresolved clock_gettime or __clock_gettime64 aliases. Runtime ABI values and compiler endian constants must agree. Guest ELFs, raw command outputs, receipts and partial failures remain in the private task output and must be fetched before derived-image cleanup. No source or image substitution after results.
